# 身份与访问管理模块需求

| 属性 | 内容 |
| --- | --- |
| 模块 | Identity and Access Management（IAM） |
| 工程边界 | `platform/iam` |
| 文档状态 | 草案，待产品、安全与架构评审 |
| 主要需求编号 | `UR-IAM-*`、`SR-IAM-*` |

身份与访问管理（Identity and Access Management，IAM）是管理身份、角色和访问权限的专业术语，来源见 [NIST IAM Glossary](https://csrc.nist.gov/glossary/term/Identity_and_access_management)。本项目在该范围内进一步纳入认证、会话和服务身份能力。

## 1. 目标与边界

IAM 模块回答三个问题：主体是谁、主体当前以什么可信状态访问、主体在当前租户可以执行什么操作。

负责：

- 自然人和服务身份的生命周期。
- 认证凭据、认证过程、会话和撤销。
- 角色、权限、策略与授权关系。
- 高风险操作的强化认证要求。
- 身份联合和用户生命周期同步扩展点。

不负责：

- 租户本身的生命周期和组织结构。
- 套餐、订阅、权益、配额和菜单内容。
- 业务资源的最终租户归属判断。
- 具体外部身份产品或协议选型。

## 2. 参与角色与依赖

| 参与方 | 主要职责 |
| --- | --- |
| 租户用户 | 验证身份、管理自身安全信息、选择有权访问的租户 |
| 租户管理员 | 管理本租户角色绑定和成员访问范围 |
| 平台管理员 | 管理平台级身份策略和高权限主体 |
| 安全人员 | 调查异常登录、撤销访问并验证传播结果 |
| 业务应用 | 验证可信访问上下文并执行权限判断 |
| Tenant 模块 | 提供当前租户、成员关系和成员状态 |
| Application 模块 | 提供应用命名空间、权限声明和所有权 |
| Audit 模块 | 保存身份、授权和安全关键事件 |

## 3. 用户需求

| 编号 | 优先级 | 用户需求 | 详细验收要点 |
| --- | --- | --- | --- |
| UR-IAM-001 | P0 | 作为用户，我希望通过统一入口安全登录，以便访问所有已接入应用。 | 启用身份可以建立会话；无效凭据、停用、锁定或被撤销身份不能建立新会话；失败不泄露账号是否存在。 |
| UR-IAM-002 | P0 | 作为多租户用户，我希望选择并明确看到当前租户。 | 只能选择有效成员关系对应的租户；切换后产生新的可信上下文；原租户上下文不能被继续误用。 |
| UR-IAM-003 | P0 | 作为租户管理员，我希望通过角色和权限管理成员访问范围。 | 授权仅在当前租户生效；默认拒绝；不能授予操作者自身无权管理的角色或平台级权限。 |
| UR-IAM-004 | P0 | 作为业务负责人，我希望业务接口获得一致、可验证的授权结果。 | 页面隐藏不能替代授权；直接访问未授权接口仍被拒绝；决策可关联策略版本和原因代码。 |
| UR-IAM-005 | P1 | 作为企业租户管理员，我希望接入企业身份系统。 | 外部身份可与本地稳定身份建立受控关联；联合失败、账号冲突和身份源停用有明确处理。 |
| UR-IAM-006 | P1 | 作为企业租户管理员，我希望自动同步成员生命周期。 | 新增、更新、停用和恢复可幂等处理；来源、同步批次、冲突及结果可审计。 |
| UR-IAM-007 | P0 | 作为安全人员，我希望高权限账号使用更强认证。 | 平台管理员和敏感操作可以要求多因素或等效强化认证；认证强度不足时拒绝或要求重新验证。 |
| UR-IAM-008 | P1 | 作为业务应用，我希望安全地进行非人工调用。 | 服务身份与自然人身份可区分、可轮换、可撤销、可限权；不能默认继承创建者权限。 |

## 4. 系统需求

| 编号 | 优先级 | 系统行为 | 主要来源 |
| --- | --- | --- | --- |
| SR-IAM-001 | P0 | 系统应管理自然人、服务身份及其稳定唯一标识，并区分主体类型、状态和来源。 | `UR-IAM-001`、`UR-IAM-008` |
| SR-IAM-002 | P0 | 系统应支持建立、续期、轮换、撤销和终止安全会话或等效访问凭证，并限制有效期和并发使用。 | `UR-IAM-001`、`UR-IAM-007` |
| SR-IAM-003 | P0 | 系统应管理角色、权限、角色权限关系和租户成员授权关系，并保留变更版本。 | `UR-IAM-003` |
| SR-IAM-004 | P0 | 系统应支持应用在受控命名空间内注册权限定义，拒绝代码冲突、所有权冲突和不兼容重定义。 | `UR-IAM-004` |
| SR-IAM-005 | P0 | 系统应提供一致的授权决策或可验证授权上下文，至少表达主体、租户、资源、动作、结果和决策版本。 | `UR-IAM-003`、`UR-IAM-004` |
| SR-IAM-006 | P0 | 系统应支持用户、凭据、会话、身份源和服务身份的停用与撤销，并可判断撤销是否已传播完成。 | `UR-IAM-001`、`UR-IAM-008` |
| SR-IAM-007 | P0 | 系统应按主体、操作、资源和风险条件要求强化认证，并记录认证时间与保证等级。 | `UR-IAM-007` |
| SR-IAM-008 | P1 | 系统应提供开放标准身份联合扩展点，具体协议、版本、声明映射和安全配置由 ADR 与契约确认。 | `UR-IAM-005` |
| SR-IAM-009 | P1 | 系统应提供开放标准用户生命周期同步扩展点，支持批次、游标、幂等、冲突和部分失败。 | `UR-IAM-006` |
| SR-IAM-010 | P0 | 访问凭证应遵循最小披露，不承载易膨胀或无法及时失效的完整权限、权益和菜单集合。 | `UR-IAM-004` |

## 5. 状态与不变量

### 5.1 身份状态

```text
Pending → Active → Locked → Active
                   ↓
                Disabled → Deleted
```

- `Pending` 身份未完成激活，不能建立普通业务会话。
- `Locked` 表示临时安全限制，解除前不能建立新会话。
- `Disabled` 表示管理停用；已有会话必须进入撤销流程。
- `Deleted` 是完成保留与删除流程后的终态，稳定标识不得重新分配给其他主体。

### 5.2 会话状态

```text
Created → Active → Expired
             ├──→ Revoked
             └──→ Terminated
```

- 会话只能关联一个主体；一次业务访问只能具有一个当前租户。
- 租户切换必须重新验证成员关系，并产生可区分的新上下文或上下文版本。
- 身份停用、凭据泄露、成员失效或高风险事件可以触发相关会话撤销。
- 已撤销、过期或终止的会话不得恢复为活动状态。

### 5.3 授权不变量

- 未明确允许时默认拒绝。
- 平台级权限与租户级权限使用不同作用域，租户管理员不能授予平台级权限。
- 权限代码在应用命名空间内稳定；弃用后不得赋予新语义。
- 授权判断必须同时验证成员关系和资源租户归属；角色命中不能替代隔离检查。
- 决策所依赖的身份、成员关系、角色和策略都必须可追溯到版本。

## 6. 数据与隐私要求

- 身份内部标识与登录名、邮箱、手机号等可变标识分离。
- 凭据秘密只保存安全验证所需的受保护表示，不能在日志、事件或错误中返回。
- 外部身份关联必须记录身份源、外部主体标识、绑定状态和验证时间。
- 会话记录至少包含主体、创建时间、最后活动时间、到期时间、撤销状态和安全上下文，不默认记录完整请求内容。
- 认证日志对外展示时应脱敏网络地址、设备信息和个人信息，并按职责控制访问。

## 7. 接口与状态传播要求

- 登录、续期、撤销和授权接口必须定义统一错误语义、限流和防枚举策略。
- IAM 向运行时提供稳定主体标识、主体类型、当前租户、会话标识、认证时间和保证等级。
- 身份、会话、角色绑定和权限定义变化必须产生带对象版本的通知。
- 消费方必须能检测通知重复、乱序和版本缺口，并通过快照重新同步。
- 运行时授权视图缓存必须设置最大生存时间；高风险撤销超过传播目标时采用安全失败策略。

## 8. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-IAM-001 | 启用用户使用有效凭据登录 | 建立受保护会话，记录认证方式、时间和关联审计事件 |
| AC-IAM-002 | 攻击者分别提交不存在账号和错误密码 | 对外错误不可用于枚举账号，内部仍能区分并监控原因 |
| AC-IAM-003 | 同一用户属于两个租户并切换当前租户 | 新上下文只含目标租户；旧租户权限不能在目标租户生效 |
| AC-IAM-004 | 租户管理员授予超出自身管理范围的角色 | 请求被拒绝，角色绑定不变，并记录高风险拒绝事件 |
| AC-IAM-005 | 用户绕过页面直接调用无权限 API | 即使导航隐藏规则失效，业务 API 仍返回授权拒绝 |
| AC-IAM-006 | 安全人员停用主体并撤销全部会话 | 新登录立即拒绝；已有访问在传播目标内失效；结果可验证 |
| AC-IAM-007 | 低保证等级会话发起高风险操作 | 系统要求强化认证；完成前不得执行目标操作 |
| AC-IAM-008 | 相同外部同步批次被重复提交 | 不重复创建成员或身份；返回相同处理结果或已处理状态 |
| AC-IAM-009 | 服务身份凭据被轮换或撤销 | 旧凭据在规定窗口内失效，新凭据权限不超过既定作用域 |
| AC-IAM-010 | 企业用户通过已配置的外部身份源登录 | 外部主体被安全映射到唯一平台身份；冲突、禁用和声明不满足策略时拒绝登录 |

## 9. 待确认事项

- 首批本地认证方式、外部身份源和账号恢复范围。
- 身份联合与生命周期同步的首批协议和强制安全配置。
- 会话并发限制、设备管理、自助退出全部会话和风险检测策略。
- 平台管理员与敏感租户操作的强化认证等级。
- 授权采用本地评估、远程决策还是混合方式，以及撤权传播失败策略。
