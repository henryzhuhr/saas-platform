# 产品与订阅模块需求

| 属性 | 内容 |
| --- | --- |
| 模块 | Subscription |
| 工程边界 | `platform/subscription` |
| 文档状态 | 草案，待产品、运营与架构评审 |
| 主要需求编号 | `UR-SUB-001`、`UR-SUB-002`、`SR-SUB-001`、`SR-SUB-002`、`SR-SUB-007` |

## 1. 目标与边界

Subscription 模块管理平台可销售或可开通的产品、功能目录、不可变套餐版本和租户订阅事实，明确“租户在什么时间订阅了哪个版本”。

负责：

- 产品、功能和套餐版本的生命周期。
- 租户订阅的开通、续期、升级、降级、暂停、恢复和终止。
- 计划变更的生效时间、来源、原因和执行结果。
- 订阅事实的版本化通知。

不负责：

- 支付收单、账单、税务、开票和财务对账。
- 最终权益、覆盖优先级、配额扣减和用量计量。
- 用户角色权限和应用导航。
- 通过修改历史套餐版本实现租户差异化。

## 2. 参与角色与依赖

| 参与方 | 主要职责 |
| --- | --- |
| 平台运营人员 | 定义产品和套餐版本，执行订阅变更 |
| 租户管理员 | 查看当前订阅、有效期和计划变更 |
| 外部订单系统 | 可选地提供经过验证的订单或合同事实 |
| Tenant 模块 | 提供租户状态和稳定标识 |
| Entitlement 模块 | 根据套餐版本和订阅状态计算最终权益 |
| Application 模块 | 结合订阅和权益决定租户应用开通条件 |
| Audit 模块 | 记录商业配置和订阅关键变化 |

## 5. 状态与业务规则

### 5.1 产品与套餐版本

```text
Draft → Scheduled → Active → Retired
  └──────────────→ Cancelled
```

- `Draft` 可修改，不能用于新订阅生效。
- `Scheduled` 内容冻结，只能取消或按受控流程替换计划。
- `Active` 可用于新订阅和续期；内容不可原地修改。
- `Retired` 不再接受新订阅，但既有订阅在迁移或到期前仍可引用。
- 已被任何订阅或审计记录引用的套餐版本不得物理删除或复用版本号。

### 5.2 订阅状态

```text
Pending → Active → Suspended → Active
              ├──→ Expired
              └──→ Terminated
```

- 一个租户对同一订阅范围在任一时点只能有一个最终生效订阅事实。
- `Pending` 表示等待生效时间或外部条件，不提前授予正式权益。
- `Suspended`、`Expired` 和 `Terminated` 对权益的影响由明确策略决定，默认不继续授予新增使用权。
- 升级和降级必须区分立即生效、下周期生效和指定时间生效。
- 续期不能覆盖历史周期，必须追加新的有效期或变更记录。
- 终止是业务事实，不等于立即删除订阅记录和历史权益证据。

### 5.3 计划变更

- 同一订阅同一时点不能存在互相冲突的多个计划变更。
- 创建计划前必须预览目标套餐、时间、生效后状态和权益差异。
- 计划执行采用幂等状态机；重试不能重复生成周期或通知。
- 计划执行失败必须记录失败步骤、可重试性和对当前有效订阅的影响。
- 取消计划只影响尚未生效的变更，不反向篡改已生效事实。

## 6. 数据与集成要求

- 产品代码、功能代码、套餐代码和版本标识在其命名空间内稳定，不得重用为不同语义。
- 所有时间区间采用明确的开始包含、结束排除或其他统一边界规则。
- 外部订单或合同编号仅作为来源关联，不能直接替代平台订阅标识。
- 外部系统重复发送、乱序发送或暂时不可用时，平台必须保持当前有效订阅确定。
- 订阅查询应能返回当前状态、当前套餐版本、有效期、待生效变更和最近一次失败。
- 批量开通或续期必须限制单批规模，并返回逐租户处理结果。

## 7. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-SUB-001 | 运营人员修改尚未发布的套餐草稿 | 草稿版本更新并保留编辑记录，不影响任何生效订阅 |
| AC-SUB-002 | 尝试修改已生效套餐版本内容 | 请求被拒绝；必须创建新版本，既有租户继续引用原版本 |
| AC-SUB-003 | 相同幂等键重复开通订阅 | 只产生一个订阅及一次逻辑状态变化 |
| AC-SUB-004 | 为已有有效订阅安排下周期降级 | 当前周期保持不变，待生效计划可查询，目标时间原子切换 |
| AC-SUB-005 | 同一订阅创建两个冲突的同时间计划 | 后提交请求被拒绝或显式替换，不能留下歧义状态 |
| AC-SUB-006 | 外部订单事件重复或乱序到达 | 根据来源版本和幂等规则处理，不回退已确认的新状态 |
| AC-SUB-007 | 计划变更执行期间下游权益模块不可用 | 当前订阅事实保持确定，任务进入可重试状态并暴露失败 |
| AC-SUB-008 | 租户管理员查询订阅 | 返回当前状态、有效期、套餐版本及待生效变更，不暴露其他租户信息 |

## 8. 待确认事项

- 首期是否仅支持运营人员人工开通，还是接收订单或合同系统事实。
- 试用、宽限期、自动续期和取消续期是否属于首个闭环。
- 升级、降级、暂停和终止的默认生效时间及恢复规则。
- 一个租户是否可同时订阅多个产品，以及产品间互斥和依赖规则。
- 套餐版本数量、历史保留周期和批量迁移规模。
