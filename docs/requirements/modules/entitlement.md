# 权益与配额模块需求

| 属性 | 内容 |
| --- | --- |
| 模块 | Entitlement |
| 工程边界 | `platform/entitlement` |
| 文档状态 | 草案，待产品、运营与架构评审 |
| 主要需求编号 | `UR-SUB-003` 至 `UR-SUB-006`、`SR-SUB-003` 至 `SR-SUB-006`、`SR-SUB-008` |

## 1. 目标与边界

Entitlement 模块回答“当前租户在当前时间拥有什么功能和额度”，把产品套餐、订阅状态、租户覆盖和临时授权解析为稳定、可解释的最终权益。

负责：

- 功能权益定义和值类型。
- 套餐权益、租户覆盖和临时授权的合并计算。
- 资源配额、用量、预留量、剩余额度和超限语义。
- 高频运行时读取、批量判断和可重建派生视图。

不负责：

- 产品销售、订阅生命周期和支付结算。
- 用户角色权限和业务资源租户归属。
- 页面导航结构。
- 未经业务契约定义的任意计费规则。

现有编号中的 `SUB` 前缀来自订阅与权益首次共同建模。为保持引用稳定不重命名；后续新增权益需求使用 `UR-ENT-*` 和 `SR-ENT-*`。

## 2. 参与角色与依赖

| 参与方 | 主要职责 |
| --- | --- |
| 平台运营人员 | 定义权益、配额和租户覆盖 |
| 租户管理员 | 查看租户最终权益、额度和拒绝原因 |
| 业务应用 | 按权益代码判断功能并报告或消费用量 |
| Subscription 模块 | 提供当前订阅和不可变套餐版本 |
| Tenant 模块 | 提供租户状态和稳定标识 |
| Application 模块 | 声明应用所需权益代码 |
| Audit 模块 | 记录高风险覆盖、配额调整和用量异常 |

## 5. 权益模型与不变量

### 5.1 权益类型

| 类型 | 示例语义 | 必须定义 |
| --- | --- | --- |
| 布尔 | 是否允许使用审计能力 | 默认值、生效条件 |
| 数值配额 | 最大成员数、存储量 | 单位、上限、是否可预留、超限策略 |
| 枚举 | 支持等级、隔离等级 | 允许值、顺序或比较规则 |

- 权益代码在应用或平台命名空间内稳定，值类型发布后不能原地改变。
- 未定义、未授予或无法确认的权益默认视为不可用，除非该权益明确声明安全默认值。
- 业务应用只能依据权益代码和值判断，不能依据套餐名称或租户标签推断商业能力。

### 5.2 计算优先级

建议的逻辑层次为：

```text
平台安全限制
  → 租户状态限制
  → 当前订阅套餐权益
  → 经授权的租户覆盖
  → 有时间边界的临时授权
  → 最终生效权益
```

最终优先级必须在契约中固定。任何覆盖都不能绕过平台安全限制、租户停用或数据隔离要求。

### 5.3 配额语义

```text
可用额度 = 上限 - 已确认用量 - 有效预留量
```

- `Unlimited` 必须作为显式语义表达，不能用任意大整数代替。
- 硬配额在确认消费前必须防止并发超卖，或定义明确的有界超限策略。
- 软配额可以允许短时超限，但必须告警、记录和说明后续处理。
- 预留必须有所有者、数量、创建时间、到期时间和幂等标识。
- 用量修正不能覆盖历史事实，应记录差异、原因和修正者。

## 6. 一致性、缓存与失败策略

- 权益结果必须携带租户、权益代码、结果版本和计算时间。
- 订阅、覆盖或租户状态变化后，派生视图必须在 `NFR-PERF-007` 窗口内失效。
- 消费方发现版本缺口、缓存过期或签名/完整性失败时，不能继续无限期使用未知状态。
- 降权、撤销和租户停用优先安全收窄；普通升级可以采用有界最终一致。
- 管理预览与运行时判断应使用同一计算规则；预览必须标识尚未生效。
- 派生视图不是唯一事实来源，必须可从订阅、权益定义、覆盖和用量权威状态重建。

## 7. 接口与审计要求

- 权益读取至少支持单项判断、批量判断和租户权益摘要，批量请求有明确上限。
- 配额消费、预留、确认和释放必须支持幂等标识，并返回当前版本。
- 拒绝结果至少区分未定义、未授予、已过期、租户受限、额度不足和状态暂不可确认。
- 权益定义、覆盖、手工配额调整和异常用量修正必须审计。
- 用量事件必须声明租户、应用、资源类型、数量、单位、发生时间和幂等标识。

## 8. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-ENT-001 | 业务应用查询套餐已授予的布尔权益 | 返回允许、来源套餐版本、结果版本和有效期 |
| AC-ENT-002 | 业务应用查询不存在的权益代码 | 返回稳定的未定义或默认拒绝结果，不因套餐名称猜测 |
| AC-ENT-003 | 租户覆盖临时提高数值配额 | 生效窗口内返回覆盖值和解释链，过期后恢复基础值 |
| AC-ENT-004 | 两个并发请求消费最后一个硬配额单位 | 最多一个成功，另一个收到额度不足且不会产生负余额 |
| AC-ENT-005 | 相同幂等标识重复提交用量 | 只计入一次，并返回已处理结果 |
| AC-ENT-006 | 权益撤销通知丢失导致版本缺口 | 消费方检测缺口并重新同步，不无限期使用旧允许结果 |
| AC-ENT-007 | 租户管理员查看最终权益 | 展示与运行时相同版本的值、来源、覆盖和有效期 |
| AC-ENT-008 | 运营人员尝试覆盖平台安全限制 | 请求被拒绝并审计，最终权益保持安全限制 |

## 9. 待确认事项

- 首批权益值类型、代码命名空间和版本兼容规则。
- 配额采用查询式、预留确认式还是事件计量式，分别适用于哪些资源。
- 硬配额允许的最大并发误差和跨区域一致性要求。
- 用量数据权威来源、迟到事件、修正和对账责任。
- 权益覆盖审批等级、最大有效期和紧急撤销流程。
