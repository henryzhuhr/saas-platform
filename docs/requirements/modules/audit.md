# 审计与运营治理模块需求

| 属性 | 内容 |
| --- | --- |
| 模块 | Audit |
| 工程边界 | `platform/audit` |
| 文档状态 | 草案，待安全、运维、合规与架构评审 |
| 主要需求编号 | `UR-AUD-*`、`UR-OPS-*`、`SR-AUD-*` |

## 1. 目标与边界

Audit 模块保存平台关键行为和安全事件的可验证证据，并提供跨模块关联、租户级查询和运营治理入口，使管理员能够回答“谁在何时对什么执行了什么操作、结果如何、影响了哪些状态”。

负责：

- 平台审计事件契约、接收、只追加保存和完整性保护。
- 按权限提供租户级与平台级审计查询、导出和留存。
- 跨模块操作的关联标识和关键事件链路。
- 业务应用审计事件接入规范。
- 租户级运行指标治理、异常租户定位和隔离操作证据。

不负责：

- 普通调试日志、全量调用日志和业务分析仓库。
- 替代各模块自身的权威业务状态。
- 收集与安全、运营或合规目的无关的个人信息。
- 直接实现所有监控、告警和遥测存储产品。

## 2. 参与角色与依赖

| 参与方 | 主要职责 |
| --- | --- |
| 安全与审计人员 | 查询证据、调查事件、导出受控报告 |
| 平台管理员 | 查看经授权的跨模块操作结果 |
| 租户管理员 | 查看本租户范围内允许公开的审计记录 |
| 运维人员 | 按租户诊断容量、错误、延迟和异常负载 |
| 业务应用 | 按版本化契约上报业务关键事件和允许的租户维度 |
| 所有平台模块 | 在本地业务动作完成边界产生可靠审计事实 |
| IAM 模块 | 提供审计查询授权和主体身份 |
| Tenant 模块 | 提供租户归属、状态和隔离操作上下文 |

## 3. 用户需求

| 编号 | 优先级 | 用户需求 | 详细验收要点 |
| --- | --- | --- | --- |
| UR-AUD-001 | P0 | 作为审计人员，我希望查询平台关键操作和安全事件。 | 可按授权范围查询身份、租户、订阅、应用和发布变化；记录包含主体、目标、时间、结果和来源。 |
| UR-AUD-002 | P0 | 作为管理员，我希望追踪一次跨模块操作。 | 管理请求、状态变更、异步任务、事件和外部发布通过关联标识形成有序时间线。 |
| UR-AUD-003 | P1 | 作为业务负责人，我希望通过统一契约上报业务审计事件。 | 事件包含租户、主体、应用、动作、对象和结果；来源可验证；重复上报不产生重复事实。 |
| UR-OPS-001 | P0 | 作为运维人员，我希望按租户观察使用量、错误和延迟。 | 可以定位异常租户和受影响服务，同时限制高基数、个人信息和跨租户可见性。 |
| UR-OPS-002 | P0 | 作为运维人员，我希望限制异常租户对共享资源的影响。 | 可实施租户级配额、限流、公平调度或隔离，并验证对目标与其他租户的影响。 |
| UR-OPS-003 | P0 | 作为发布人员，我希望交付物可追溯和可回滚。 | 每个交付物可关联产品版本、源代码、契约、依赖、迁移和发布记录。 |

## 4. 系统需求

| 编号 | 优先级 | 系统行为 | 主要来源 |
| --- | --- | --- | --- |
| SR-AUD-001 | P0 | 系统应记录身份、授权、租户、订阅、权益、应用、导航和发布关键事件。 | `UR-AUD-001`、`UR-AUD-002` |
| SR-AUD-002 | P0 | 审计记录至少包含事件类型、时间、主体、租户、应用、动作、对象、结果、来源和关联标识。 | `UR-AUD-001`、`UR-AUD-003` |
| SR-AUD-003 | P0 | 审计记录必须只追加，并能通过完整性证据或受控存储检测未授权修改和删除。 | `UR-AUD-001` |
| SR-AUD-004 | P0 | 系统应按租户、主体、动作、对象、结果、事件类型和时间范围检索审计记录。 | `UR-AUD-001`、`UR-AUD-002` |
| SR-AUD-005 | P1 | 系统应定义业务应用上报审计和用量事件的版本化、幂等、可验证来源契约。 | `UR-AUD-003` |
| SR-AUD-006 | P0 | 运行指标、日志和追踪必须能在受控范围内按租户分析，同时遵守隐私和高基数限制。 | `UR-OPS-001`、`UR-OPS-002` |

交付物追溯和运行要求还受[系统需求](../system-requirements.md)第 8 节约束。

## 5. 事件分类与最小字段

| 类别 | 示例 | 最低保护级别 |
| --- | --- | --- |
| 安全事件 | 登录失败、强化认证、撤销、越权和跨租户拒绝 | 高完整性、受限访问、快速可检索 |
| 管理事件 | 角色绑定、租户状态、订阅、权益覆盖和应用审核 | 只追加、操作者与变更前后版本可追溯 |
| 发布事件 | 候选、审核、发布、执行面确认、漂移和回滚 | 关联快照摘要、目标和结果 |
| 业务审计事件 | 业务应用声明的关键动作 | 租户隔离、来源验证、版本化 Schema |
| 运营治理事件 | 限流、隔离、扩容、恢复和故障演练 | 关联触发原因、影响范围和恢复结果 |

每条审计记录至少表达：

- 全局唯一事件标识、事件类型和 Schema 版本。
- 事件发生时间、平台接收时间和可信时间来源。
- 主体标识、主体类型、当前租户和应用。
- 动作、目标对象类型与标识、执行结果和原因代码。
- 请求追踪标识、业务关联标识和上游事件标识。
- 来源组件、来源版本和必要的完整性信息。

不得默认记录密码、完整访问凭证、密钥、敏感请求正文或不必要的个人信息。

## 6. 不变量与失败处理

- 审计事件一旦接受不得原地修改；纠正通过追加更正事件并引用原事件。
- 事件标识或幂等键重复且内容相同时返回已接受；内容不同则拒绝并告警。
- 平台关键写操作必须在明确的可靠边界记录审计意图或事实，不能仅依赖易丢失异步日志。
- 审计汇聚暂时不可用时，业务模块采用有界缓冲或可靠转发；缓冲耗尽时按风险决定拒绝高风险写入或触发降级。
- 租户管理员只能查询本租户允许公开的事件；平台跨租户查询需要独立权限和查询审计。
- 留存到期后的删除必须按照策略执行并生成可验证记录，不能由普通管理员任意删除单条事件。
- 审计查询本身属于敏感操作，需要记录查询者、范围、目的和导出结果。

## 7. 查询、导出与运营要求

- 查询必须限定时间范围、分页大小和授权租户范围，禁止无界全量扫描。
- 稳定游标需要处理相同时间戳事件，并保证翻页不重复、不遗漏。
- 大规模导出采用异步任务，提供状态、到期时间、完整性摘要和受控下载。
- 高基数用户、会话和全部租户标识不作为无界常驻指标标签；使用分层聚合、日志/追踪关联和按需诊断。
- 异常租户隔离操作必须记录触发指标、阈值、作用范围、操作者、持续时间和恢复条件。
- 交付追溯至少关联 Git Commit、产品版本、组件版本、契约版本、内容摘要和发布环境。

## 8. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-AUD-001 | 管理员修改租户角色绑定 | 生成包含操作者、租户、目标成员、前后版本和结果的审计事件 |
| AC-AUD-002 | 一次应用开通跨多个模块推进 | 所有步骤可通过同一关联标识形成时间线，并区分成功、待处理和失败 |
| AC-AUD-003 | 相同审计事件重复上报 | 只保存一条逻辑事实；内容冲突时拒绝并告警 |
| AC-AUD-004 | 租户管理员查询其他租户审计 | 请求被拒绝，且查询拒绝本身被记录 |
| AC-AUD-005 | 审计汇聚依赖短时不可用 | 关键事件不丢失，恢复后按顺序或可重放方式汇聚 |
| AC-AUD-006 | 普通管理员尝试修改已保存事件 | 操作被拒绝，并能够检测或记录未授权尝试 |
| AC-AUD-007 | 运维人员按租户定位突发错误 | 可识别目标租户和影响范围，不需要把全部用户作为指标标签 |
| AC-AUD-008 | 对异常租户启用隔离并随后恢复 | 两次操作均记录原因、影响、结果和关联指标，无关租户保持正常 |
| AC-AUD-009 | 导出大时间范围审计数据 | 创建受控异步任务，输出有完整性摘要和访问到期时间 |
| AC-AUD-010 | 根据一次生产发布查询交付来源 | 能关联产品版本、Git Commit、组件与契约版本、内容摘要和发布结果 |

## 9. 待确认事项

- 各事件类别的留存时间、数据驻留、法律保全和删除规则。
- 租户管理员、平台审计人员和安全响应人员的查询字段与脱敏差异。
- 完整性保护采用的逻辑等级、证明范围和外部审计要求。
- 高风险写入在审计能力不可用时应拒绝还是进入受控降级。
- 首批业务审计事件、用量事件和交付物追溯契约范围。
