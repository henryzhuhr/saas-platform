# 租户、组织与隔离模块需求

| 属性 | 内容 |
| --- | --- |
| 模块 | Tenant |
| 工程边界 | `platform/tenant` |
| 文档状态 | 草案，待产品、安全与架构评审 |
| 主要需求编号 | `UR-TEN-*`、`SR-TEN-*` |

## 1. 目标与边界

Tenant 模块管理 SaaS 客户边界及其成员关系，使任何平台或业务操作都能确定唯一、可信的租户上下文，并为共享、独占或混合隔离方式提供稳定语义。

负责：

- 租户创建、启用、暂停、恢复、关闭和最终删除的生命周期。
- 租户成员、邀请、加入、退出和停用。
- 租户内组织结构、标签、层级属性和隔离策略声明。
- 租户状态、成员关系和隔离配置的版本化变更。

不负责：

- 用户凭据、认证会话和角色权限定义。
- 产品套餐、订阅、权益和支付结算。
- 业务应用自身数据的具体存储隔离实现。
- 将组织节点误作独立租户安全边界。

## 2. 参与角色与依赖

| 参与方 | 主要职责 |
| --- | --- |
| 平台管理员 | 创建租户、处理生命周期和全局隔离策略 |
| 租户管理员 | 管理本租户成员和组织结构 |
| 租户成员 | 接受邀请、查看和退出有权访问的租户 |
| 运维与安全人员 | 观察异常租户、执行隔离并调查跨租户拒绝 |
| IAM 模块 | 提供稳定主体标识、角色和授权能力 |
| Subscription 模块 | 根据租户状态管理订阅生效条件 |
| Application 模块 | 管理租户可开通的应用范围 |
| 业务应用 | 对每个业务资源执行租户归属检查 |

## 3. 用户需求

| 编号 | 优先级 | 用户需求 | 详细验收要点 |
| --- | --- | --- | --- |
| UR-TEN-001 | P0 | 作为平台管理员，我希望管理租户完整生命周期。 | 每次状态变化有前置条件、生效时间、原因和操作者；暂停、关闭和删除对访问与数据处理的影响明确。 |
| UR-TEN-002 | P0 | 作为租户管理员，我希望管理本租户成员。 | 只能查看和管理当前租户成员；邀请、重新发送、取消、停用和恢复均可追踪且幂等。 |
| UR-TEN-003 | P0 | 作为平台管理员，我希望用标签和分层属性管理租户。 | 标签具有受控命名、值类型和所有者；可用于运营、能力开通、流量和观测，但不能直接绕过权限。 |
| UR-TEN-004 | P1 | 作为租户管理员，我希望按组织或部门管理成员。 | 组织节点始终属于一个租户；移动、停用和删除节点不会产生跨租户成员关系。 |
| UR-TEN-005 | P0 | 作为租户，我希望其他租户的访问和负载不影响我的安全与核心体验。 | 跨租户访问全部拒绝；异常租户可限流、隔离和单独观测；恢复过程不影响无关租户。 |
| UR-TEN-006 | P0 | 作为平台管理员，我希望查看租户全局状态。 | 可聚合查看成员、订阅、权益、应用、流量与异常摘要，同时受跨租户权限和敏感信息最小化约束。 |

## 4. 系统需求

| 编号 | 优先级 | 系统行为 | 主要来源 |
| --- | --- | --- | --- |
| SR-TEN-001 | P0 | 系统应管理租户稳定标识、显示名称、状态、层级、标签、隔离等级和生命周期时间。 | `UR-TEN-001`、`UR-TEN-003` |
| SR-TEN-002 | P0 | 系统应支持一个用户加入多个租户，并在每个请求中确定唯一、可信的当前租户。 | `UR-TEN-002` |
| SR-TEN-003 | P0 | 系统应管理成员状态、邀请、加入、退出和停用流程，并防止重复成员关系。 | `UR-TEN-002` |
| SR-TEN-004 | P1 | 系统应支持可扩展组织或部门结构，且所有节点、关系和成员分配都不能跨越租户边界。 | `UR-TEN-004` |
| SR-TEN-005 | P0 | 非正常状态租户的访问策略必须显式定义；未匹配特例时默认拒绝业务访问。 | `UR-TEN-001` |
| SR-TEN-006 | P0 | 所有租户资源访问必须同时验证主体权限、当前租户和目标资源租户归属。 | `UR-TEN-005` |
| SR-TEN-007 | P0 | 系统应支持共享、独占和混合隔离策略抽象，并允许租户在满足条件时迁移隔离单元。 | `UR-TEN-005` |
| SR-TEN-008 | P0 | 租户状态、标签、成员关系和隔离策略变化必须产生带版本、时间和原因的变更通知。 | `UR-TEN-001`、`UR-TEN-003`、`UR-TEN-006` |

## 5. 状态与不变量

### 5.1 租户状态

```text
Provisioning → Active ↔ Suspended → Closing → Closed → Deleted
      │            │
      └──→ Failed  └──→ Expired
```

- `Provisioning` 期间只能执行开通和恢复操作，不能提供普通业务访问。
- `Suspended` 默认禁止业务写入和新会话，可保留经授权的管理、导出或恢复入口。
- `Expired` 表示时间或商业状态导致的受限状态，其允许行为必须由策略明确。
- `Closing` 和 `Closed` 必须冻结新开通，完成导出、保留和依赖清理检查。
- `Deleted` 是最终状态；稳定租户标识不得重新分配。
- `Failed` 必须保留失败步骤和重试信息，不能与从未创建混淆。

### 5.2 成员状态

```text
Invited → Active → Suspended → Active
    │         └──→ Left
    └──→ Expired
Active / Suspended → Removed
```

- 同一主体在同一租户最多存在一个当前有效成员关系。
- 接受邀请时必须验证邀请目标与当前主体匹配，并检查邀请是否过期或撤销。
- 移除成员必须撤销其租户角色绑定和相关运行时访问，但不删除审计历史。
- 租户必须保留至少一个满足治理规则的管理员，最后管理员退出需要转移职责或平台介入。

### 5.3 隔离不变量

- `tenant_id` 只能来自可信访问上下文或经授权的平台跨租户操作上下文。
- 所有租户拥有对象必须带稳定租户或隔离域键。
- 跨租户管理操作必须同时记录操作者范围、目标租户、理由和结果。
- 组织、标签、角色和应用开通都不能扩大租户安全边界。
- 隔离单元迁移期间，读写归属必须唯一可判定，不允许同一数据被两个租户访问。

## 6. 数据与生命周期要求

- 租户代码、显示名称和外部客户编号分离；可变业务标识不能替代内部稳定标识。
- 标签定义至少包含命名空间、键、值类型、所有者和可用于的策略范围。
- 组织树必须检测循环、孤立节点和跨租户父子关系。
- 租户删除必须定义停用、保留、导出、依赖清理、最终删除和证明生成阶段。
- 全局租户视图可以使用派生数据，但必须展示数据版本或更新时间，并可从权威模块重建。

## 7. 接口与状态传播要求

- 创建租户和邀请成员必须支持幂等键，重复请求不能生成重复租户或邀请。
- 列表使用稳定游标并默认限定调用者可管理的租户范围。
- 租户状态通知必须先于或与访问收窄同步传播；状态不明时运行时默认拒绝。
- 成员和标签的批量变更必须有单批上限、部分失败结果和可重试语义。
- 隔离单元迁移提供计划、执行、校验、切换、回退和审计状态，不暴露具体基础设施产品模型。

## 8. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-TEN-001 | 相同幂等键重复创建租户 | 只产生一个租户，返回相同标识和可判断的处理状态 |
| AC-TEN-002 | 邀请已属于该租户的用户 | 不生成重复成员，返回现有关系或明确冲突 |
| AC-TEN-003 | 用户接受发给其他主体或已过期的邀请 | 请求被拒绝，不创建成员关系，并记录安全相关结果 |
| AC-TEN-004 | 多租户用户切换到无成员关系的租户 | 无法建立目标租户上下文，且不泄露目标租户详细信息 |
| AC-TEN-005 | 租户管理员查询其他租户成员 | 请求被默认拒绝并产生跨租户拒绝证据 |
| AC-TEN-006 | 平台暂停一个异常租户 | 目标租户访问在传播目标内收窄，其他租户关键路径保持正常 |
| AC-TEN-007 | 删除仍有有效订阅或应用依赖的租户 | 进入待处理或拒绝状态，返回未完成依赖，不直接最终删除 |
| AC-TEN-008 | 组织节点被移动到另一租户父节点下 | 系统拒绝跨租户关系，原组织结构不变 |
| AC-TEN-009 | 隔离单元迁移在切换前失败 | 继续使用原有效单元，可重试或回退，租户归属不产生歧义 |
| AC-TEN-010 | 平台更新用于灰度的租户标签 | 记录标签版本和操作者，下游可检测变化且未授权调用不能修改标签 |
| AC-TEN-011 | 平台管理员查看租户全局摘要 | 返回各来源版本和更新时间，敏感字段按权限脱敏，单个依赖失败可定位 |

## 9. 待确认事项

- 租户层级是否只用于运营分组，还是需要集团与子租户业务关系。
- 暂停、过期、关闭状态下允许的只读、导出和管理员操作。
- 最大单租户成员量、组织深度、标签数量和批量操作规模。
- 共享、独占和混合隔离等级的商业、法规和迁移触发条件。
- 租户数据导出、保留、匿名化和最终删除证明要求。
