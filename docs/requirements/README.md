# 需求文档地图

本目录描述产品目标、用户场景、系统能力、模块需求、约束和验收标准。根文档维护全局事实，详细领域需求按模块拆分，实现渐进式阅读。

## 文档

- [项目用户需求](user-requirements.md)：产品目标、目标用户、核心旅程、优先级和范围边界。
- [项目系统需求](system-requirements.md)：系统边界、跨模块接口、数据与一致性、非功能需求和系统验收标准。
- [模块需求地图](modules/README.md)：8 个平台领域的详细用户需求、系统需求、状态、不变量和验收场景。
- [需求追踪矩阵](traceability.md)：维护用户需求到系统需求和验收场景的映射。
- [项目术语表](glossary.md)：统一身份、租户、授权、权益、路由和可靠性术语。
- [规范依据矩阵](standards-and-evidence.md)：映射安全、可靠性和多租户需求到权威标准及行业指南。

## 变更顺序

1. 先在用户需求中确认角色、目标、范围和核心旅程。
2. 在对应模块文档中更新带编号的用户需求、系统需求和验收场景。
3. 更新需求追踪矩阵及安全、可靠性和多租户规范依据。
4. 更新相关架构、ADR、公开契约和测试。
5. 保留已被引用的需求编号；废弃需求应指向替代项。
