# SaaS Platform 用户需求

| 属性 | 内容 |
| --- | --- |
| 文档状态 | 草案，待产品与架构评审 |
| 版本 | 0.2 |
| 目标阶段 | 平台控制面能力基线 |
| 设计规模 | 万级活跃租户、百万级注册用户 |

## 1. 产品定位

SaaS Platform 是面向多个业务应用的统一 SaaS 控制面。它管理用户与租户关系、访问权限、产品套餐、订阅权益、应用接入、导航入口、流量规则和审计信息，使业务团队不必重复建设通用平台能力。

平台不是业务功能的集合。业务应用继续拥有自己的业务流程、业务数据和业务发布节奏，并通过稳定契约接入平台。

## 2. 业务目标

- 为平台运营方提供统一的租户开通、管理、订阅和治理体验。
- 为租户用户提供统一登录、租户切换、应用入口和导航体验。
- 为业务应用提供稳定的身份、授权、权益、审计和接入能力。
- 支持业务应用独立演进，不要求修改平台核心代码。
- 从设计起支持至少 10,000 个活跃租户和 1,000,000 个注册用户。
- 防止任何租户访问其他租户的数据或消耗失控影响其他租户。
- 使关键变更、发布结果和安全事件可追踪、可解释、可恢复。

## 3. 目标用户与角色

| 角色 | 主要目标 | 典型操作 |
| --- | --- | --- |
| 平台管理员 | 管理全局租户和平台能力 | 创建租户、注册应用、管理平台策略、查看全局状态 |
| 平台运营人员 | 运营产品、套餐和订阅 | 配置产品套餐、开通或变更订阅、调整租户权益 |
| 平台发布人员 | 管理流量和版本风险 | 校验规则、预览影响范围、发布、灰度和回滚 |
| 安全与审计人员 | 发现风险并追溯关键行为 | 查询登录、授权、跨租户操作和配置变更记录 |
| 租户管理员 | 管理本租户组织和成员 | 邀请成员、分配角色、配置应用入口、查看订阅 |
| 租户成员 | 使用获准的业务能力 | 登录、切换租户、访问应用、完成业务操作 |
| 业务应用负责人 | 将业务应用接入平台 | 声明权限、权益、导航、接口和流量需求 |
| 运维人员 | 保证平台稳定运行 | 观察容量、隔离异常租户、恢复服务和数据 |

同一自然人可以加入多个租户，也可以在不同租户中拥有不同角色。每次操作必须具有唯一且可信的当前租户上下文。

## 4. 核心用户旅程

### 4.1 租户开通

```text
创建租户
  → 建立租户管理员
  → 开通产品和订阅
  → 计算功能权益与资源配额
  → 启用业务应用
  → 邀请成员并分配角色
  → 用户登录并访问获准能力
```

### 4.2 业务应用接入

```text
业务负责人提交版本化应用清单
  → 声明权限、权益、导航和流量需求
  → 平台执行格式、引用、冲突和安全校验
  → 管理员审核并启用应用版本
  → 配置发布到对应执行组件
  → 获准租户和用户访问应用
```

### 4.3 用户访问

```text
验证用户身份
  → 确认当前租户和有效成员关系
  → 计算用户权限
  → 计算租户权益和配额
  → 返回可见应用与导航
  → 业务接口再次执行授权与租户隔离检查
```

### 4.4 灰度与回滚

```text
创建候选应用版本
  → 配置租户范围或标签规则
  → 预览命中租户和规则冲突
  → 发布不可变配置版本
  → 观察租户级指标和错误
  → 扩大范围或回滚到已知有效版本
```

## 5. 用户需求清单

优先级说明：`P0` 是平台能力基线，`P1` 是进入稳定版本前的优先能力，`P2` 是后续增强。

### 5.1 身份与访问管理

身份与访问管理（Identity and Access Management，IAM）是管理身份、角色和访问权限的专业术语，来源见 [NIST IAM Glossary](https://csrc.nist.gov/glossary/term/Identity_and_access_management)。本项目在此范围内进一步纳入认证和会话能力。

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-IAM-001 | P0 | 作为用户，我希望通过统一入口安全登录，以便访问所有已接入应用。 | 启用用户可建立会话；停用、锁定或已撤销用户不能继续访问。 |
| UR-IAM-002 | P0 | 作为多租户用户，我希望选择并明确看到当前租户。 | 每次业务操作只有一个当前租户，不能由客户端伪造租户身份。 |
| UR-IAM-003 | P0 | 作为租户管理员，我希望通过角色和权限管理成员访问范围。 | 用户在不同租户的授权相互独立；默认拒绝未明确授予的操作。 |
| UR-IAM-004 | P0 | 作为业务负责人，我希望业务接口获得一致、可验证的授权结果。 | 隐藏菜单不能替代后端授权；直接访问未授权接口仍被拒绝。 |
| UR-IAM-005 | P1 | 作为企业租户管理员，我希望接入企业身份系统。 | 支持基于开放标准的身份联合，具体协议由后续决策确认。 |
| UR-IAM-006 | P1 | 作为企业租户管理员，我希望自动同步成员生命周期。 | 外部成员新增、更新、停用可幂等同步并保留审计记录。 |
| UR-IAM-007 | P0 | 作为安全人员，我希望高权限账号使用更强认证。 | 平台管理员和敏感操作支持多因素或等效的强化认证策略。 |
| UR-IAM-008 | P1 | 作为业务应用，我希望安全地进行非人工调用。 | 服务身份与自然人身份可区分、可撤销、可限权并可审计。 |

### 5.2 租户、组织与隔离

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-TEN-001 | P0 | 作为平台管理员，我希望管理租户完整生命周期。 | 创建、启用、暂停、过期、关闭和删除流程有明确状态及审计。 |
| UR-TEN-002 | P0 | 作为租户管理员，我希望管理本租户成员。 | 只能查看和管理当前租户成员，跨租户操作默认拒绝。 |
| UR-TEN-003 | P0 | 作为平台管理员，我希望用标签和分层属性管理租户。 | 标签可用于运营、能力开通、流量策略和可观测性分组。 |
| UR-TEN-004 | P1 | 作为租户管理员，我希望按组织或部门管理成员。 | 组织结构不改变租户安全边界，并可用于授权策略。 |
| UR-TEN-005 | P0 | 作为租户，我希望其他租户的访问和负载不影响我的安全与核心体验。 | 跨租户访问被阻断；异常租户可被限流、隔离和单独观测。 |
| UR-TEN-006 | P0 | 作为平台管理员，我希望查看租户全局状态。 | 可聚合查看租户、成员、订阅、权益、应用、流量配置和异常状态。 |

### 5.3 产品、套餐、订阅与权益

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-SUB-001 | P0 | 作为运营人员，我希望定义产品、功能和版本化套餐。 | 已生效套餐版本不可被静默修改，变更可追溯。 |
| UR-SUB-002 | P0 | 作为运营人员，我希望开通、续期、升级、降级、暂停或终止订阅。 | 状态、有效期和生效时点明确，重复操作不会产生重复结果。 |
| UR-SUB-003 | P0 | 作为业务应用，我希望按权益代码判断能力是否可用。 | 业务不依赖套餐名称，能获得权益值、来源、版本和有效期。 |
| UR-SUB-004 | P0 | 作为业务应用，我希望查询并消费租户配额。 | 配额上限、已用量、剩余额度和超限行为定义明确。 |
| UR-SUB-005 | P1 | 作为运营人员，我希望为单个租户追加、覆盖或撤销权益。 | 优先级确定，变更有生效时间、原因和审计记录。 |
| UR-SUB-006 | P0 | 作为租户管理员，我希望看到与实际执行一致的订阅和权益。 | 页面结果与业务接口的最终判断一致，并能解释拒绝原因。 |

### 5.4 应用接入与生命周期

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-APP-001 | P0 | 作为业务负责人，我希望通过版本化清单注册应用能力。 | 清单可声明身份接入、权限、权益、导航、接口和流量需求。 |
| UR-APP-002 | P0 | 作为平台管理员，我希望审核、启用、暂停和下线应用版本。 | 状态变化会一致地影响新会话、导航和后续配置发布。 |
| UR-APP-003 | P0 | 作为业务负责人，我希望平台在生效前发现配置错误。 | 标识冲突、无效引用、路径冲突和不安全配置有明确诊断。 |
| UR-APP-004 | P0 | 作为业务负责人，我希望应用独立版本化和发布。 | 应用版本可独立演进，并可追溯到平台契约和产品发布。 |
| UR-APP-005 | P0 | 作为平台管理员，我希望按租户控制应用开通范围。 | 只有应用、租户、订阅和权益均有效时才允许使用。 |

### 5.5 导航与页面入口

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-NAV-001 | P0 | 作为用户，我希望登录后看到稳定的应用和导航入口。 | 返回有序、无孤立节点且适用于当前租户的导航结构。 |
| UR-NAV-002 | P0 | 作为管理员，我希望导航入口关联权限和权益。 | 可见性同时考虑应用状态、成员权限、租户权益和租户配置。 |
| UR-NAV-003 | P0 | 作为租户管理员，我希望定制本租户导航。 | 租户定制只能进一步收窄展示范围，不能绕过授权和权益。 |
| UR-NAV-004 | P1 | 作为管理员，我希望预览指定用户的最终导航。 | 结果能够解释每个入口显示或隐藏的原因。 |

```text
导航可见
= 应用已启用
AND 租户已开通
AND 用户拥有所需权限
AND 租户拥有所需权益
AND 租户未隐藏入口
```

### 5.6 流量路由与发布控制

本节管理网络请求的流量路由，不包含浏览器页面路由。

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-ROUTE-001 | P0 | 作为发布人员，我希望集中管理业务应用的流量入口和目标。 | 规则可表达入口、匹配条件、目标版本和必要策略，不依赖特定网关产品。 |
| UR-ROUTE-002 | P0 | 作为发布人员，我希望在发布前校验和预览规则。 | 可发现冲突、无效目标、越权范围和规则优先级问题。 |
| UR-ROUTE-003 | P0 | 作为发布人员，我希望把已审核配置发布到网关执行面。 | 发布显式、可追踪且原子切换；失败不破坏上一有效版本。 |
| UR-ROUTE-004 | P0 | 作为发布人员，我希望快速回滚流量配置。 | 可恢复到任一受支持历史快照，并产生新的审计记录。 |
| UR-ROUTE-005 | P1 | 作为发布人员，我希望按租户、标签或显式名单灰度。 | 发布前可预览命中范围，规则优先级稳定且可解释。 |

### 5.7 审计、安全与运营

| 编号 | 优先级 | 用户需求 | 验收要点 |
| --- | --- | --- | --- |
| UR-AUD-001 | P0 | 作为审计人员，我希望查询平台关键操作和安全事件。 | 身份、授权、租户、订阅、应用和发布变更包含操作者、对象、时间和结果。 |
| UR-AUD-002 | P0 | 作为管理员，我希望追踪一次跨模块操作。 | 管理请求、状态变更、事件和外部发布可通过关联标识串联。 |
| UR-AUD-003 | P1 | 作为业务负责人，我希望通过统一契约上报业务审计事件。 | 事件包含租户、主体、应用、动作、对象和结果，并可校验来源。 |
| UR-OPS-001 | P0 | 作为运维人员，我希望按租户观察使用量、错误和延迟。 | 指标可定位异常租户，同时保护个人信息和敏感数据。 |
| UR-OPS-002 | P0 | 作为运维人员，我希望限制异常租户对共享资源的影响。 | 支持租户级配额、限流、公平调度或隔离策略。 |
| UR-OPS-003 | P0 | 作为发布人员，我希望交付物可追溯和可回滚。 | 每个交付物可追溯到版本、源代码、契约和迁移记录。 |

## 6. 范围边界

### 6.1 平台能力基线

- 身份验证、会话、用户、租户成员、角色、权限和强化认证。
- 租户生命周期、可信租户上下文、隔离策略和租户级运营视图。
- 产品、套餐版本、订阅、功能权益和资源配额。
- 应用清单、版本、审核、启停和租户开通范围。
- 导航树和基于应用、权限、权益及租户配置的可见性计算。
- 流量规则的草稿、校验、不可变发布、执行面适配和回滚。
- 平台关键操作、安全事件和跨模块关联审计。
- 版本化平台接口、事件、应用清单和至少一种接入 SDK。
- 面向万级租户、百万级用户的容量验证、租户公平性和可恢复性。

### 6.2 当前不包含

- 支付收单、财务账单、税务、开票和对账。
- 具体业务应用的数据模型、业务流程和业务页面。
- 完整低代码平台、工作流引擎或应用市场交易能力。
- 所有身份协议、所有 SDK 语言和所有部署环境的一次性支持。
- 尚未由合规、地域和业务目标驱动的跨地域多活。

不在当前范围不表示架构可以阻断未来能力；数据所有权、契约版本和扩展点必须允许后续演进。

## 7. 规模与成功标准

设计容量基线是至少 10,000 个活跃租户和 1,000,000 个注册用户。该数字表示系统需要容纳的对象规模，不等于同时在线人数或每秒请求数。

成功标准包括：

1. 在约定负载模型下完成容量、峰值、故障和恢复测试。
2. 最大租户或异常租户不能无边界占用共享资源。
3. 租户数量增长时，不需要为每个租户手工部署或修改平台代码。
4. 用户、成员关系、会话、权限、权益和审计查询不存在无界全量扫描。
5. 控制面短时不可用时，业务流量执行面继续使用上一份有效配置。
6. 新业务应用通过稳定契约接入，不依赖平台内部数据结构。

## 8. 待确认事项

- 峰值登录量、并发会话、平台查询吞吐和应用业务流量模型。
- 首批业务应用数量、最大单租户规模和租户间负载差异。
- 身份联合、用户同步和服务身份所需的首批开放协议。
- 共享、独占或混合租户隔离等级及其商业化策略。
- 数据分类、审计留存、数据驻留和删除合规要求。
- 内部服务目标与对外服务等级协议的最终数值。
- 首期订阅是否仅支持人工开通，还是同时接入订单系统。
- 前端应用集成模式和网关执行产品的技术选型。
