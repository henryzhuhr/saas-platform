# ADR-0007：IAM 作为可独立使用的 Go 子项目

| 属性 | 内容 |
| --- | --- |
| 状态 | Superseded，由 ADR-0008 替代 Git 集成方式 |
| 日期 | 2026-11-11 |
| 来源 | 用户要求 IAM README 明确技术栈，并将 platform/iam 作为可独立的项目维护 |
| 关联 | [ADR-0005](0005-iam-module-layout-and-comments.md)、[ADR-0006](0006-iam-gorm-model-layer.md) |

维护者随后明确要求独立 Git 子仓库。2026-11-11 的 [ADR-0008](0008-iam-git-submodule.md) 将普通目录维护改为 Git submodule；目录、Go 模块名、项目内文档与配置自包含原则继续保留。以下原决定保留用于追溯，不再作为当前 Git 集成基线。

## 背景

IAM 已有独立 `go.mod`、内部导入、源码、迁移和测试，但 README 的命令仍从 Monorepo 根目录出发，必要接口和实现文档也存放在父仓库中。仅有编译模块边界不足以让单独取得该目录的人顺利了解、开发和运行项目。

## 决策

- IAM 是 `platform/iam` 内的独立 Go 服务项目，模块名继续使用 `iam`，当前随 Monorepo 普通目录进行版本控制。
- 项目 README 说明定位、边界、从实际 `go.mod` 核对的技术栈、目录、配置、项目内构建/测试/启动命令和外部能力依赖。
- 运行只依赖项目自身代码、Go 依赖及明确的外部服务，不依赖根 npm/Python 工具、其他模块内部源码或父级配置文件。
- 项目内保存 `.env.example`、`.gitignore` 和现有 Apache 2.0 许可证副本。配置示例不含有效生产秘密，程序不隐式加载 dotenv 文件。
- API 契约与实现说明正文迁入 `platform/iam/docs`，通过项目内 README 逐层索引；原仓库路径保留导航，避免产生第二套正文或失效链接。
- 迁移 SQL 已随程序嵌入，构建出的可执行文件不依赖父仓库或运行时源码目录。
- 通过将整个项目目录复制到仓库外并设置 `GOWORK=off` 验证独立构建、测试及配置启动。

## 边界与取舍

独立项目边界不改变平台领域所有权。租户成员和应用所有权仍经权威接口确认，短信/邮件与事件仍经外部能力交付；未配置时继续采用原默认拒绝或可靠排队策略。生产容量和可靠性未因项目独立化而获得验收。

保留父仓库说明作为唯一操作文档会让迁出后的项目缺乏资料；复制两套 API 正文则容易漂移。本决定把运行所需事实收归项目，Monorepo 保留全局需求、工程治理与历史决策，并导航到项目正文。

## 迁移与验证

原 `api/iam-v1.md` 与 `docs/architecture/iam-implementation.md` 保留原路径但转为导航，正文分别位于项目内 `docs/api.md` 与 `docs/implementation.md`。HTTP v1 语义、数据库表与认证规则保持不变。

验收检查包括模块内文档相对链接不越界、`go.mod/go.sum` 可独立解析、关闭 workspace 后编译与测试、嵌入 SQL 迁移可执行，以及项目自身命令启动后进程存活接口可访问。
