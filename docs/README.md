# 文档总地图

`docs/` 是项目需求、架构决策和工程规范的事实系统。使用者从本页进入对应分类，再由分类索引进入具体文档，避免一次加载无关上下文。

## 分类地图

| 分类 | 索引 | 内容 |
| --- | --- | --- |
| 需求 | [requirements/README.md](requirements/README.md) | 用户需求、系统需求、范围和验收标准 |
| 架构 | [architecture/README.md](architecture/README.md) | 架构总览、项目结构和 ADR |
| 工程规范 | [standards/README.md](standards/README.md) | Markdown、文档地图和未来工程约束 |

## 导航规则

- 本页只维护一级分类，不直接替代分类索引。
- 每个含 Markdown 的子目录必须有自己的 `README.md`。
- 新文档必须加入最近的分类索引，父索引只链接下一级索引。
- 需求变化先更新需求文档，再更新架构、契约、实现和测试。
- 所有文档修改必须运行 `npm run docs:check`。

## 文档状态

- `草案`：内容正在讨论，不作为开发承诺。
- `待评审`：内容已具备评审条件，仍可能调整。
- `已确认`：可作为设计、开发和验收依据。
- `已废弃`：保留历史记录，但不再生效，并应指向替代文档。
